# 棒球家庭会议：填写、共同查看与阶段性决策

正式入口：`https://jingsen.cc/baseball/familymeeting/query`。

## 使用流程

1. 发起人使用现有 Jingsen 后台登录，创建一次会议。后台 Baseball 页面也有入口。
2. 分别分享爸爸、妈妈的专属链接。链接随机凭证在 URL fragment 中，不进入服务器访问日志；请只交给对应参与人。
3. 独立填写七组问题。允许留空与「暂时不知道」，不打分；自动同步自己的草稿，失败时保留本机备份。
4. 双方各自提交后，「开始共同查看」可用。每个浏览器需要输入服务器配置的会议密码才能获得十二小时的查看授权；授权保存在 sessionStorage，分享链接不附带授权。
5. 按「今晚怎么谈」的45分钟流程先理解、再比较六种道路，最后记录共识、分歧、条件、分工、行动和复盘日期。
6. 孩子参与状态单独记录：父母暂定／已听意见尚未确认／孩子共同确认。没有听取孩子意见时不会自动称为三方共识。
7. 可以导出 Markdown、JSON、复制文本和打印。导出只包含已提交答案及当前共同记录，不带密码、链接凭证或个人未提交草稿。

六条道路：留在现俱乐部、加入外部球队、参与／自行组队、降低投入继续打、阶段性暂停、结束棒球转向其他活动。所有选项均无默认选择。结束棒球是有效的讨论选项。

## 实现与访问边界

- `api/familymeeting.py`：独立页面、限定资产、现有 Admin 管理、专属链接访问与密码查看。
- `services/familymeeting_service.py`：独立 SQLite、个人草稿与提交快照、双方就绪状态、查看授权、共同笔记及乐观版本检查。
- `static/familymeeting/`：无外部字体或第三方脚本，中文响应式页面。`questions.json` 同时用于前台呈现与服务端校验。
- 创建／恢复管理链接要求现有 Admin 会话。管理页面不直接返回草稿；服务器管理员仍然具有主机和数据的管理权限。
- 所有角色在开始查看前均收不到另一方的答案。双方提交仍不会自动释放；需要显式点击并输入密码。
- 在第一次共同查看前继续修改，会撤回该方就绪状态，需重新提交。共同查看开启后，新修改仍留在自己的草稿，重新提交才更新共享快照。
- 查看授权与会议、角色及有效期绑定。每五次密码错误会锁定三分钟。
- 新增后台登录返回路径仅放行家庭会议的两个精确地址，保留原有 Admin 路径校验，避免开放重定向。

## 数据与部署

- 默认独立数据库：`data/family-meetings.sqlite3`，WAL 模式，文件权限0600；不修改现有学习中心 SQLite Schema v5。
- 隔离测试可设置 `FAMILYMEETING_DATABASE_PATH`。
- 线上 `.env` 使用 `FAMILYMEETING_UNLOCK_HASH` 保存 PBKDF2-SHA256 加盐摘要。明文密码不进入前端、版本库、备份导出或发布记录。
- 生产沿用现有 LearningCenter 服务与 Nginx；无需新增依赖、开放端口或修改其他站点。
- 发布前备份代码、完整 data 与 `.env`，SQLite 使用在线 backup 获取一致快照；仅快进更新已核实的源码变更，不重置或恢复线上活动数据。
- 更新后验证导入与页面路由，再平滑重载 `learningcenter.service` 的 Gunicorn 主进程。服务健康后核对独立入口、资源、匿名数据访问和双方提交流程。
- 回退到上一个源码提交并平滑重载即可。不要回退或覆盖已经产生的家庭会议记录与其他线上数据。
